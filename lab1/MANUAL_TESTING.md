# Самостоятельная проверка этапа №1 (Windows 11 / PowerShell)

Все проверки выполняются без Codex. Не меняйте Python-код. Нужны Pixi, Chrome/Edge и интернет для установки/Grabber/первой подготовки токенизатора. Ollama и Docker не нужны. Окончательно принимайте этап только после этих проверок. Сохраняйте скриншоты и текстовые результаты в собственной папке для защиты; не публикуйте токены.

## 1. Открытие проекта в VS Code

- **Действие:** VS Code → File → Open Folder → `C:\MyWorkP\OWASP-RAG`. Terminal → New Terminal, выберите PowerShell. Выполните:

  ```powershell
  Set-Location C:\MyWorkP\OWASP-RAG\lab1
  pixi --version
  ```

- **Ожидаемый результат:** видны README, configs, src, tests и pixi.lock; Pixi сообщает версию.
- **Признак успеха:** текущая папка терминала заканчивается на `OWASP-RAG\lab1`, команда Pixi доступна.
- **Для защиты:** скриншот структуры и версии Pixi.

## 2. Установка зависимостей

- **Действие:** из `lab1` выполните:

  ```powershell
  pixi install --locked
  pixi run smoke
  ```

- **Ожидаемый результат:** среда `.pixi` установлена из lockfile, local smoke показывает `passed`, network — `not requested`.
- **Признак успеха:** обе команды завершились с кодом 0 (`$LASTEXITCODE` сразу после команды). Не устанавливайте pip-пакеты глобально и не создавайте venv.
- **Для защиты:** вывод установки и smoke. При ошибке сети повторите после восстановления интернета.

## 3. Запуск приложения

- **Действие:** выполните `pixi run app`, оставьте терминал открытым. Откройте Chrome или Edge, перейдите на [http://127.0.0.1:8000](http://127.0.0.1:8000).
- **Ожидаемый результат:** Uvicorn сообщает `Application startup complete`, открывается тёмный интерфейс OWASP-RAG.
- **Признак успеха:** страница загружается, нет красного сообщения об ошибке соединения. Сервер слушает `127.0.0.1:8000`.
- **Для защиты:** окно браузера и терминал с адресом сервера.

## 4. Dashboard и пустой корпус

- **Действие:** откройте Dashboard, запишите счётчики. Если локальные данные уже подготовлены, используйте отдельный пустой каталог: остановите сервер `Ctrl+C`, выполните команды ниже и снова откройте страницу.

  ```powershell
  $env:OWASP_DATA_DIR = 'C:\MyWorkP\OWASP-RAG\lab1\data\manual-empty'
  pixi run app
  ```

- **Ожидаемый результат:** для нового каталога счётчики 0, Knowledge Base показывает пустой корпус. ChromaDB ожидает этап №2, Ollama/Langfuse — №3, Evaluation — №4. AI Chat/Search/Experiments показывают будущий этап.
- **Признак успеха:** приложение не падает при пустой базе и не имитирует ответы LLM.
- **Для защиты:** пустой Dashboard и будущий раздел. Далее можно продолжить проверки в этом каталоге. Чтобы вернуться к основному после остановки сервера: `Remove-Item Env:OWASP_DATA_DIR`, затем `pixi run app`. Не удаляйте основной `data`.

## 5. Скачивание через UI

- **Действие:** Knowledge Base → «Обновить документы». Наблюдайте панель «Текущая операция». Во время работы попробуйте нажать кнопку ещё раз.
- **Ожидаемый результат:** кнопки временно отключены, интерфейс остаётся доступным; счётчик прогресса меняется. На чистом каталоге итог `succeeded`, `new: 55`, `errors: []`.
- **Признак успеха:** загружены реальные материалы OWASP; в списке есть темы, названия и официальные ссылки. Если сайт изменился или сеть недоступна, должны быть показаны реальные ошибки/partial, а не выдуманный успех.
- **Для защиты:** начальный/финальный прогресс, раскрытый JSON результата с commit и количеством новых документов.

## 6. Проверка числа и metadata

- **Действие:** сравните Knowledge Base, Dashboard и CLI во втором PowerShell:

  ```powershell
  Set-Location C:\MyWorkP\OWASP-RAG\lab1
  # Если сервер запущен с OWASP_DATA_DIR, установите ту же переменную здесь.
  pixi run stats
  ```

- **Ожидаемый результат:** 55 активных документов. `downloaded_documents` может быть больше 55, если сохранены старые out_of_scope/deleted документы. В подготовленном рабочем каталоге сохранены также две устаревшие копии, исключённые из итоговой выборки: всего 57, активных 55. На чистом каталоге будет 55/55.
- **Признак успеха:** активные/обработанные счётчики согласованы. Название документа открывает просмотрщик с датой скачивания, commit и raw Markdown; дата изменения честно указана неизвестной.
- **Для защиты:** вывод stats, metadata одного документа и официальная ссылка. Даты в JSON — UTC, в UI — локальное время браузера.

## 7. Повторный Grabber

- **Действие:** вновь нажмите «Обновить документы», затем раскройте результат операции.
- **Ожидаемый результат:** если upstream commit/содержимое не менялись — `new: 0`, `changed: 0`, `unchanged: 55`.
- **Признак успеха:** число документов не выросло; ID прежние. Изменение исходного OWASP может законно дать changed/new; запишите commit обоих запусков.
- **Для защиты:** два JSON-результата и сравнение счётчиков. Имитировать изменения правкой Python-кода не требуется: change detection проверяется отдельным mocked тестом.

## 8. Проверка отсутствия дубликатов и конфликтов

- **Действие:** повторите Grabber ещё раз. Во время работы попробуйте `pixi run grab` во втором терминале с тем же каталогом данных.
- **Ожидаемый результат:** неизменённые документы пропускаются. Конкурирующий CLI завершится с понятным сообщением «Уже выполняется операция» и кодом 1; API при конфликте использует 409. Операция может завершиться слишком быстро — тогда оба последовательных запуска допустимы.
- **Признак успеха:** количество записей не растёт, нет параллельных мутаций. Детерминированный конфликт дополнительно проверяется integration test.
- **Для защиты:** результат repeat и, если удалось попасть в активный интервал, сообщение о конфликте.

## 9. Preprocessing

- **Действие:** в Knowledge Base выберите Section-based, 256 tokens, 0% overlap → «Запустить обработку». Первый запуск может скачать JSON токенизатора; это указано в статусе. При необходимости заранее: `pixi run tokenizer`.
- **Ожидаемый результат:** `succeeded`, обработано 55 активных документов, chunks > 0. Появляются `data/processed/*.jsonl` и `index.json`.
- **Признак успеха:** количество chunks в JSON результата совпадает с Dashboard для последней конфигурации. Число зависит от snapshot/конфигурации; точное фактическое число текущей поставки записано в VALIDATION.md.
- **Для защиты:** параметры, configuration_id, source commit, document_count и chunk_count.

## 10. Просмотр raw и chunks; четыре стратегии

- **Действие:** откройте SQL Injection Prevention Cheat Sheet по названию. Проверьте raw, переключитесь на Chunks, раскройте Metadata. При необходимости используйте «Следующие chunks». Повторите preprocessing для Fixed-size, Fixed-size + overlap (10% или 20%), Paragraph-based и Section-based. В просмотрщике выберите сохранённую конфигурацию.
- **Ожидаемый результат:** видны текст SQL/HTTP, heading_path, chunk_id, document_id, source_commit, token_count. `0 < token_count <= chunk_size`. Разные конфигурации доступны отдельно.
- **Признак успеха:** полезный технический текст сохраняется; короткий последний chunk допустим. При повторе одинаковой конфигурации chunk IDs прежние. Большой code block может пересечь границу chunks; raw остаётся целиком.
- **Для защиты:** SQL chunk, metadata и результаты четырёх конфигураций. Это проверка pipeline, а не измерение качества retrieval.

## 11. Сохранение после перезапуска

- **Действие:** запишите stats. Остановите сервер `Ctrl+C`; снова выполните `pixi run app` в той же папке с тем же `OWASP_DATA_DIR`, обновите браузер.
- **Ожидаемый результат:** документы, JSONL, счётчики, последняя операция и история ошибок сохранились.
- **Признак успеха:** значения совпадают, ранее созданные chunks открываются без интернета (токенизатор уже закеширован).
- **Для защиты:** screenshots до/после. Резервная копия — копирование `data` после завершения операций.

## 12. Ошибка сети и восстановление

- **Действие:** при уже работающем локальном сервере временно отключите интернет обычным способом, нажмите «Обновить документы». Дождитесь ограниченных retry/timeout (обычно до двух минут). Затем восстановите интернет и повторите Grabber.
- **Ожидаемый результат:** операция заканчивается `failed` с понятной сетевой ошибкой; Dashboard → Последние ошибки показывает запись. Существующий корпус остаётся доступен. После восстановления сети новый запуск завершается успешно. Старую ошибку из истории успех не скрывает.
- **Признак успеха:** нет бесконечной загрузки, сервер/страница не падают, raw/manifest сохранены.
- **Для защиты:** сообщение ошибки, журнал и успешный повтор. Альтернатива без переключения сети: mocked тесты `test_timeout_retries_exhausted` и `test_failed_network_is_visible_and_recovers`; явно укажите, что это автоматическая симуляция, а не реальное отключение сети.

## 13. Автоматические тесты и smoke

- **Действие:** дождитесь завершения операций и выполните:

  ```powershell
  pixi run test
  pixi run lint
  pixi run smoke
  pixi run smoke --network
  ```

- **Ожидаемый результат:** pytest показывает число passed, нет failed/errors; lint проходит; local smoke проходит. Сетевая smoke отдельно сообщает успех либо конкретную недоступность сети.
- **Признак успеха:** `$LASTEXITCODE` равен 0 после каждого успешного запуска. Сетевой smoke, который не запускали, не записывайте как passed.
- **Для защиты:** полные итоговые строки, время запуска, commit проекта (`git rev-parse HEAD`) и source commit из stats. Тесты не скачивают реальные документы и не портят основной data.

## 14. Технические логи

- **Действие:** откройте `C:\MyWorkP\OWASP-RAG\lab1\logs\application.log` в VS Code либо:

  ```powershell

  ```

- **Ожидаемый результат:** JSON-строки с timestamp, level, module, operation, message; для неожиданных ошибок — тип и места вызовов. Ротация: 2 MB, три резервных файла.
- **Признак успеха:** операции и ошибки объяснимы, токен/Authorization не выводятся, в UI нет необработанных stack traces.
- **Для защиты:** несколько строк нормального запуска и ошибки (без приватных данных).

## 15. Если приложение не запускается

- **Действие:** проверьте текущую папку, `pixi --version`, повторите `pixi install --locked`, затем `pixi run smoke`. При занятом порте остановите свой предыдущий сервер `Ctrl+C`; не завершайте неизвестные процессы. При ошибке YAML восстановите конфигурацию из Git или своей копии и перезапустите сервер. При ошибке manifest сначала сохраните копию всего data, затем восстановите manifest/raw из резервной копии либо используйте новый `OWASP_DATA_DIR` и Grabber.
- **Ожидаемый результат:** причина конкретна: сеть, YAML, занятый порт, права на каталог или повреждённые данные. Нет необходимости редактировать Python.
- **Признак успеха:** local smoke и `/api/health` снова доступны. Если JSON токенизатора повреждён, остановите операции, удалите только файл `data/tokenizers/614241f622f53c4eeff9890bdc4f31cfecc418b3.json` (предварительно сохранив копию при необходимости), выполните `pixi run tokenizer`. Не удаляйте raw/manifest для исправления tokenizer cache.
- **Для защиты:** исходная ошибка, выполненные команды и результат восстановления. Если причина не устранена, зафиксируйте её как проблему; не отмечайте проверку успешной.

## Дополнительная проверка прерывания

- **Действие:** во время CLI Grabber нажмите `Ctrl+C`, затем повторите `pixi run grab`.
- **Ожидаемый результат:** сохранённые документы проверяются/пропускаются, недостающие скачиваются. Interrupted-статус не блокирует новый запуск. При обычной остановке сервера фоновые задачи могут быть прерваны, поэтому перед остановкой лучше дождаться завершения.
- **Признак успеха:** валидный manifest и неизменные IDs, нет дубликатов. Атомарные checkpoints и сценарий resume также покрыты unit test.
- **Для защиты:** interrupted/повторный результат и число активных документов.

На защите объясните: blob SHA против имени файла, зачем immutable raw и manifest, различие четырёх chunkers, почему реальный tokenizer важнее количества слов, почему сейчас нет метрик качества поиска и LLM-ответов. Этапы №2–4 перечислены в ROADMAP.md.
